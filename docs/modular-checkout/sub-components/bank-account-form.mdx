## Overview

Renders a form for collecting bank account details as part of a checkout flow.

This subcomponent is **designed to be used within** the `justifi-modular-checkout`. Most of its configuration arrives as shared state through the Stencil Store, managed by the wrapper component, rather than as props on this element. The exception is `show-account-number-confirmation` below, which you may set either here or on the wrapper.

> **Note:** If you are using this sub component, you also need to provide billing information. This can be done by adding the `justifi-billing-form-full` sub component for complete billing address, the `justifi-bank-account-billing-form-simple` sub component for account owner name only, or by passing the `billingInformation` object as an argument to the `submitCheckout` method called on the `justifi-modular-checkout`. See the [modular checkout docs](../introduction) for more information.

> **Note:** If the checkout's `payment_settings.ach_payments` is `false`, this component does not render the form and logs a console warning (`[bank-account-form] ACH payments are disabled for this checkout (payment_settings.ach_payments=false).`). Prefer omitting the sub-component when ACH is off, or use `justifi-checkout-changed` / `availablePaymentMethodTypes` so your layout does not reserve an empty slot.

**Authorization** and business context are also handled by `justifi-modular-checkout`, which manages authentication tokens and related configuration.

Beyond `show-account-number-confirmation`, this component is not intended for standalone use — the parent checkout drives validation and tokenization.

### Confirming the account number

Set `show-account-number-confirmation` to render a required **Confirm Account Number** field below the account number. The form then fails validation with `The entered value does not match the account number` when the two differ, which is aimed at ACH returns caused by mistyped account numbers. It defaults to `false`, so existing integrations are unaffected.

```html
<justifi-modular-checkout auth-token="authToken" checkout-id="ch_123" show-account-number-confirmation="true">
  <justifi-bank-account-form />
</justifi-modular-checkout>
```

Setting it on `<justifi-bank-account-form>` directly also works and takes precedence over the wrapper.

> **The comparison happens inside the hosted field iframes**, so the account number never reaches the parent page.

### Events

> **Event names changed.** Every event below also fires under its old, unprefixed
> name — `justifi-error` also fires as `error-event`, and so on — so an existing
> integration keeps working untouched. The old names are deprecated and go away in
> the next major release; new code should listen for the `justifi-` ones.

- Emits the same `submit` / `error` events as other modular rails via the parent checkout; no direct listeners required.
